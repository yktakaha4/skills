# 現在のタスクをアーカイブする

現在のタスクだけを、利用中の生成AIツールが提供する標準機能でアーカイブする。独自の状態管理、ファイル移動、タグ付け、要約の保存などでアーカイブを模倣しない。

## 対象を確定する

1. 「現在のタスク」が、いま開いているtask、thread、chat、conversationのいずれを指すか、利用中のツールの用語に読み替える。
2. ユーザーが別のタスクを明示していない限り、現在のタスクだけを対象にする。複数のタスクをまとめてアーカイブしない。
3. 明示的なアーカイブ依頼がなければ実行しない。会話が完了した、ユーザーが別れを告げた、または作業が止まったという理由だけで暗黙にアーカイブしない。
4. 未完了のtool call、承認待ち、またはユーザーへ返すべき重要な結果がある場合は、それを完了または明示的に中断してからアーカイブする。アーカイブ依頼を、進行中の外部操作を中止する許可として扱わない。

## 標準機能を使用する

1. 現在利用している生成AIツールが提供する、task、thread、chat、conversation用の標準アーカイブ操作を探す。
2. 専用のタスク管理toolまたはAPIが利用できる場合は、それを使用する。Codexで`set_thread_archived`が利用できる場合は、現在のタスクに対してそれを使用する。
3. 専用機能があるのに、raw directive、画面操作の自動化、ローカルファイルの編集、独自script、削除操作で代用しない。
4. 標準機能を呼び出すために現在のtask IDなどが必要な場合は、実行環境が提供する現在のコンテキストから取得する。別タスクのIDを推測しない。
5. アーカイブと削除を区別する。標準のアーカイブ機能がなく削除しかできない場合は、削除せずユーザーへ伝える。

## 実行できない場合

1. 標準アーカイブ機能が現在の環境へ公開されているか確認する。
2. 利用できない場合は、成功したように装わず、利用中のツール名、確認した機能、実行できない理由を簡潔に示す。
3. ユーザー自身が標準UIから実行できる場合は、そのツールで現在のタスクをアーカイブする最短の操作を案内する。非標準の回避策や別用途のpluginを導入しない。
4. 権限、接続、機能提供の一時的な問題なら、回復後に同じ標準操作を再試行する。

## 結果を伝える

標準機能の成功結果を確認してから、現在のタスクをアーカイブしたことだけを簡潔に伝える。確認できなければ、アーカイブ済みと報告しない。
