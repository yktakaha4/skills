# このリポジトリのスキルを更新する

配布元は[yktakaha4/skills](https://github.com/yktakaha4/skills)。インストール先のスキルを更新し、ソースリポジトリのpullや`make sync`で代用しない。コマンド名は`gh skill update`。

## 対象と更新方法を確認する

次を実行して、その環境のCLI仕様とインストール状況を確認する。

```bash
gh skill update --help
gh skill install --help
gh skill list --json skillName,sourceURL,scope,version,pinned,path,agentHosts
```

- ユーザー指定のエージェント、scope、ディレクトリを優先する。指定がなければ、このリポジトリ由来のスキルがすでにインストールされている場所を対象とする。ソースツリーとして列挙される`agentHosts: ["published"]`は除く。同じ実体の共有インストール先を重複処理しない。
- `sourceURL`などの追跡情報で配布元を確認する。`capy-`という名前だけでこのリポジトリ由来と判断しない。ローカル由来の場合は、記録された`local-path`とそのリポジトリのremoteを読み取りで確認する。
- 固定バージョンは維持し、既定では`--unpin`を付けない。同名スキルが別の配布元に属する場合は上書きせず、その対象だけを除外して報告する。
- 更新先に編集済みファイルがあれば保持する。元の配布内容と比較できずローカル編集の有無を判定できない場合も、上書き前に対象の内容を復元可能な別ディレクトリへ退避する。秘密を含む可能性のある内容はチャットやGitへ転載しない。
- 対象が一つもなければ、現在使用中のエージェントのuser scopeを初回インストール先とする。特定できなければ対象エージェントを確認する。別のエージェントへの新規展開やスキルの削除は行わない。

選択や承認が必要な場合は、利用可能で用途に合う構造化された選択・承認UIを優先する。通常の更新依頼で許可されている範囲の処理を、重ねて承認待ちにしない。

## インストール済みスキルを更新する

対象ディレクトリごとに、確認済みのこのリポジトリ由来のスキル名を明示して実行する。`--dir`でインストール先を限定し、同名の別インストール先を巻き込まない。以下は構文例なので、実行時には実際のパスと対象名へ置き換える。

```bash
gh skill update capy-update-skills --dir /actual/skills-directory --dry-run
gh skill update capy-update-skills --dir /actual/skills-directory --all
```

複数の対象名は同じコマンドへ列挙してよい。名前を指定しない`gh skill update --all`は、他の配布元まで更新するため使用しない。`--force`は通常の更新には付けない。更新先・取得元・固定バージョンの扱いを実行前に短く伝える。

### ローカル由来・追跡情報なしのインストール

`gh skill update`はGitHubの追跡情報がないスキルをスキップすることがある。「All skills are up to date」という出力だけで更新済みと判断しない。

このリポジトリ由来と確認できた対象は、同じインストール先へGitHubから再インストールして追跡情報を付ける。対象ファイルを退避したうえで、対象スキル名と保存先を明示する。既存ファイルの置換に必要な場合だけ`install`の`--force`を使い、その対象と退避先を伝える。配布元を確認できないものは自動で切り替えない。

```bash
gh skill install yktakaha4/skills capy-update-skills --agent codex --scope user
```

これはCodexのuser scopeへの構文例。実行時には確認済みのエージェントとscope、または実際の保存先を指定する`--dir`を使用する。ローカルのソースや追跡メタデータを手編集してGitHub由来に見せかけない。

## 新しいスキルも取得する

既定では新規スキルも取得する。ユーザーがインストール済みだけを指定した場合は追加しない。配布元の一覧とインストール済み一覧を比較し、不足するスキルを同じ対象エージェント・scopeへ追加する。一覧は`gh skill install yktakaha4/skills`を非対話モードで実行して取得できる。固定バージョンや別配布元との同名衝突を避けるため、不足する名前を個別に指定してインストールする。

`install --all --force`で既存スキルを一括上書きしない。未インストールのスキルが追加されたことと、既存スキルが更新されたことを区別して報告する。

## 結果を確認する

1. `gh skill list`で対象の保存先、配布元、バージョン、固定状態を再取得する。
2. 同じ対象名・ディレクトリで`gh skill update --dry-run`を再実行し、残る更新やスキップがないか確認する。固定スキルや明示的に除外した対象は別に報告する。
3. CLIの取得先はバージョン解決の仕様に従う。Releaseとデフォルトブランチのどちらを取得したかを確認し、未確認のまま「mainの最新」と報告しない。
4. 更新・追加したスキル、変更なし、固定・衝突・追跡情報不足によるスキップ、退避先、失敗を簡潔に報告する。権限や認証で止まった場合は必要な手動操作だけを具体的に依頼し、未更新の対象を成功扱いにしない。

このスキル自身も更新対象になり得るため、実行前に対象一覧と検証手順を保持する。ファイルの更新と現在の会話への新しい指示の反映を区別し、ツールが再読込を保証していなければ即時に反映されたと断定しない。
